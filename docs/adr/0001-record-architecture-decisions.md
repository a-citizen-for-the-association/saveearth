# 0001. アーキテクチャ上の意思決定をADRとして記録する

- 日付: 2026-09-21
- ステータス: Accepted

## コンテキスト

プロジェクトを進める中で、技術選定やアーキテクチャに関する重要な決定を行う機会が繰り返し発生する。これらの決定の背景や理由が記録されていないと、後から「なぜこうなっているのか」を追跡できず、同じ議論を繰り返したり、誤って決定を覆してしまうリスクがある。

## 決定

アーキテクチャ上重要な意思決定は `docs/adr/` 配下にADR（Architecture Decision Record）として記録する。

## 代替案

- 決定事項を都度Slackやチャットに残すのみ: 検索性・永続性に欠けるため不採用。
- 設計書にすべて記載する: 設計書は仕様の現在地を表すものであり、過去の意思決定の経緯を残す用途には向かないため、ADRとして分離する。

## 影響

- 重要な決定の経緯が `docs/adr/` を見れば追跡できるようになる。
- 決定を覆す場合は、既存ADRを書き換えず、新しいADRを追加して古いものを `Superseded` とする運用にする。
