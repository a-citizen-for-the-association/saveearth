# 0002. 本番運用(Mainnet)は単一チェーンのみで運用する

- 日付: 2026-09-21
- ステータス: Accepted

## コンテキスト

本プロジェクトはコントラクトをEthereum(mainnet, Sepolia)とPolkadot Hub(mainnet, testnet)の両方にデプロイする計画である。しかし、両チェーンにそれぞれ独立したコントラクトをデプロイすると、メンバーシップの状態(誰がメンバーか、誰が承認したか)はチェーンごとに別々に管理され、自動的には同期されない。

これを放置すると、例えば「Ethereumでは承認されたメンバーだが、Polkadot Hubでは非メンバー」という不整合が生じ、将来メンバー全体を対象に行う予定のCouncil選挙で「誰を対象に選挙するか」が定義できなくなる。

## 決定

- **開発・検証段階**では、両テストネット(Sepolia / Polkadot Hub Testnet)にデプロイし、動作確認を行う。
- **本番運用(Mainnet)では、Ethereum MainnetかPolkadot Hub Mainnetのどちらか一方のみを選び、単一チェーンで運用する。** 両チェーンでの本番同時運用は行わない。
- どちらのMainnetを選ぶかは別途決定する(未定)。
- コントラクト自体は特定チェーンに依存しない実装とし、どちらを選んでもデプロイできる状態を維持する。

## 代替案

- **クロスチェーンブリッジ/オラクルでメンバーシップを同期する**: 実装・運用コストが高く、ブリッジ自体がセキュリティリスクの主要因になりやすいため不採用。
- **各チェーンで独立したメンバーシップとして運用する(コミュニティを分割する)**: 「国際協調の枠組み」という目的上、メンバーシップが分裂することは望ましくないため不採用。

## 影響

- メンバーシップの整合性問題は「複数チェーンに同時に本番展開しない」という運用ルールで回避される。ブリッジ等の追加実装は不要。
- 将来、両チェーンでの本番運用が必要になった場合は、本ADRを見直し、クロスチェーン同期の設計を別途検討する。
